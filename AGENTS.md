# AGENTS.md

## Cursor Cloud specific instructions

### Overview

Cursor Boston is a single Next.js 16 (App Router) community platform. There is no monorepo — one `package.json`, one app. Firebase (Auth, Firestore, Storage) is the backend-as-a-service; no local database is required.

### Environment

- **Node 22** is required (see `.nvmrc`). The Cursor Cloud Dockerfile already installs it.
- `.env.local` is auto-generated by `.cursor/scripts/cloud-agent-setup.sh` from Cloud Agent secrets. If secrets are not configured, copy `.env.local.demo` to `.env.local` for demo mode.
- Demo mode renders all pages/layouts/styling; Firebase-dependent features (auth, data, storage) are gracefully disabled.

### Key commands

All commands are in `package.json`. Quick reference:

| Task | Command |
|------|---------|
| Dev server | `npm run dev` → http://localhost:3000 |
| Lint | `npm run lint` |
| Type-check | `npm run type-check` |
| Unit tests | `npm test` |
| Firestore rules tests | `npm run test:rules` (requires Firebase emulator) |
| Build | `npm run build` |

### Commit conventions

- Conventional Commits required: `type(scope): description` (e.g. `feat(auth): add token refresh`)
- The `-s` flag (DCO sign-off) is required on all commits.
- Husky pre-commit hook runs gitleaks (if installed), adds GPL headers, and runs lint-staged (`tsc --noEmit` + `eslint --fix --max-warnings=0`).
- Commitlint validates commit message format on `commit-msg` hook.

### Non-obvious caveats

- `npm run build` calls `validate-env` via the `prebuild` script; it rejects placeholder values. Use demo values from `.env.local.demo` or real Firebase credentials.
- Unit tests (`npm test`) mock Firebase env vars automatically via `config/jest.setup.js` — no Firebase setup needed.
- The dev server flag `--webpack` is intentional in the `dev` script (Next.js 16 default is Turbopack; this project uses webpack).
- PRs must target `develop` (not `main`). Only release PRs go `develop` → `main`.
